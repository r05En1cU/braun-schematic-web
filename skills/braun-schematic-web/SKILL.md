# Braun 原理图网页风格

本 skill 有两层:视觉层(本文件,所有网页都用)和讲解层(只在要把复杂系统、论文、算法讲清楚时用,叠加在视觉层之上)。讲解层有两种图:手写坐标的定理关系图(`references/theorem-schematic.md`,带证明的系统)和自动布线的算符级计算图(`references/compute-graphs.md`,论文架构、公式推导、数据通路)。

把可视化、数据看板、学习笔记、知识讲解等网页,统一做成同一套克制、直观、高级的 lo-fi 风格:Dieter Rams 时代的 Braun 产品说明书气质,DIN 风格字体,一个 Claude 陶土色点缀,全程直角,任何设备上都没有横向滚动条。

## 何时使用

- 要做:可视化网页、仪表盘、数据看板、学习笔记页、概念讲解页(含数学公式)、知识图谱/时间线、对比分析页、HTML 报告、个人工具页。
- 用户没指定别的视觉风格时,默认用这套。用户明确要别的风格(品牌规范、儿童向、游戏感)时,不要硬套,先问。
- 要把已有旧页面改成这套风格时,读 `references/migrating-legacy-pages.md`。
- 要把形式化项目(Lean 定理库、证明架构、带不变量的系统设计)讲给不懂该形式语言的读者:先按本文件搭好视觉层,再读 `references/theorem-schematic.md`。
- 要给一篇论文、一个模型结构、一段算法做导读,把计算过程画成图:读 `references/compute-graphs.md`。框里必须写算式,线必须是真实数据流,不画只有名字的框图。

## 一句话原则

**直观、好读优先于风格化。** 少即是多:分区靠留白和一条细线,不靠卡片框、阴影、渐变。全页只有一个点缀色,面积小于 1%。学它的纪律,不学复古的符号。

## 核心规则(必须遵守)

1. **底色是冷白灰**,墨是冷黑。没有暖色、没有高饱和色、没有渐变、没有阴影(只有浮层可以有一道柔和阴影)、没有噪点。
2. **没有卡片。** 区块之间只用 1px 细线(`--rule`)+ 留白分隔,区块顶部一条线,标题在线下。整页唯一的重线是主视觉顶上的 2px 墨线。
3. **字体:DIN 风格。** Barlow(正文/标题)+ 思源黑体(中文),大数字用 Barlow Semi Condensed。数字一律 `tabular-nums`。
4. **一个圆角都没有。** 全局 `border-radius: 0`;状态点、头像、步骤标记、开关、复选框都是直角方块。**SVG 的圆角是 `rx` 属性和 `stroke-linecap="round"`,也要清掉**(`rx=0`、`butt`、`miter`)。环形图段与段之间是直切口。环形仪表是唯一例外,能不用就不用。
5. **点缀色只有一个:Claude 陶土。**
   - 强调 = 在文字**下方画一条陶土线**(选中的标签、当前页、高亮词、输入框聚焦、下拉选中项)。
   - 强调型按钮 = 深一档陶土底 + 白字(`--accent-strong`,对比度约 4.8:1)。
   - 刻度条末端的指针、图表里的一条细线。
   - 每屏最多 1~3 处;大面积(柱子、色块、背景)不用点缀色。
6. **状态色全部低饱和**,只做小方块指示灯,旁边一定有文字:正常绿、注意琥珀、故障红。
7. **任何设备上都不出现横向滚动条**(见"响应式")。
8. **选中态和悬停态叠在一起也必须读得清。** 不用"深色整行填充 + 浅色字"表示选中(悬停把底色盖成浅灰后字就看不见了)。选中 = 加粗 + 下方一条陶土线;悬停 = 只改底色(`--tint`)。
9. **不做页面切换过渡。** 不用 View Transition / 滑动动画;不要"关掉过渡动画但保留 `@view-transition`",新旧页面会同时留在屏幕上、文字重叠。
10. **直观优先。** 加任何风格元素前先问:会不会增加阅读成本?会,就不加。

## 怎么用(工作流)

1. 复制 `assets/tokens.css` 和 `assets/base.css`(令牌 + 可直接用的组件样式,含堆叠表格)到页面。字体与 KaTeX 的 `<head>` 片段见 `assets/head-snippets.html`。
2. 按页面类型搭结构:学习/讲解类见 `references/learning-pages.md`;图表与图标见 `references/charts-and-icons.md`;公式见 `references/katex.md`。
3. 页面里有表格时引入 `assets/fit-tables.js`;有 KaTeX 公式时引入 `assets/fit-math.js`。计算图和讲义组件在 `assets/schematic.css`、`assets/schematic.js`。
4. 交付前运行检查脚本:`python scripts/check_viewports.py 你的页面.html`(设备尺寸、溢出、圆角、小字、公式渲染);有计算图时再跑 `python scripts/check_schematic.py 你的页面.html`(线穿框、箭头、文字溢出、窄屏清单)。并用截图肉眼复查 1440 与 390 两个宽度。
5. 单文件 HTML 交付,保存到用户的工作目录并告诉用户路径。要求页面不引用外部资源:用 `scripts/build_page.py` 内联 CSS/JS,字体子集化后以 base64 嵌入,KaTeX 在构建时预渲染。这样断网、预览面板、任何电脑上都是同一个外观。简单页面也可以用 `head-snippets.html` 的 `<link>` 方式,但外观会随环境变。

## 设计令牌(完整见 assets/tokens.css)

| 名称 | 值 | 用途 |
|---|---|---|
| `--bg` | `#E8EBEE` | 冷白灰纸,页面背景 |
| `--surface` | `#F3F5F7` | 仅浮层与输入 |
| `--ink` / `--ink-2` / `--ink-3` | `#14171A` / `#434A52` / `#5C636B` | 正文 / 次级 / 说明(在 `--bg` 上 15.0 / 7.5 / 5.1 : 1) |
| `--rule` / `--line-strong` | `#C3C9D0` / `#97A0AA` | 细线 / 强线 |
| `--accent` | `#D97757` | Claude 陶土:线条、指针、选中高亮(2.6 : 1,只做辅助强调) |
| `--accent-strong` | `#B25A3D` | 按钮底色,白字 4.8 : 1 |
| `--ok` / `--warn` / `--bad` | `#3E7D63` / `#A67C1F` / `#B5483D` | 状态小方块 |

字号:正文 15px,辅助文字 14px,可见文字不小于 14px(见反小字准则),页面标题 28px/500,区块标题 16px/600,指标 36~52px(窄体 400),主视觉大数字 56~168px(窄体 400,`clamp`)。正文行宽不超过 62 个字符。

## 响应式与设备适配(含"没有横向滚动条")

**硬性要求:下列任意尺寸下 `document.documentElement.scrollWidth === innerWidth`,页面里也不出现任何横向滚动条。**

| 类别 | 代表尺寸 | 比例 |
|---|---|---|
| 手机 | 360×740、390×844、414×896 | 9:18.5 ~ 9:19.5 |
| 平板竖屏 | 768×1024、820×1180 | 3:4 ~ 10:14 |
| 平板横屏 / 小笔记本 | 1024×768、1280×800、1366×768 | 4:3 ~ 16:10 |
| 笔记本 / 桌面 | 1440×900、1536×864、1920×1080 | 16:10 ~ 16:9 |
| 大屏 / 超宽屏 | 2560×1440、2560×1080、3440×1440 | 16:9、21:9 |

1. `<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">`。布局用流式宽度、`clamp()`、`auto-fit + minmax`;不写死像素宽度(输入框 `width:min(320px,100%)`)。
2. 内容容器 `max-width` 约 1120~1440px,`margin-inline:auto`;大屏和超宽屏不拉伸。整页用 `min-height:100dvh`。
3. 网格子项加 `min-width:0`(最常见的溢出原因:大数字、表格、长单词按最小内容宽度撑破布局)。**不要**写 `.row > div { min-width: 0 }` 这种宽泛规则,它会让本该换行的弹性行改成硬挤;只给确实会撑破的文本块加。
4. 长字符串(邮箱、密钥、URL):`overflow-wrap:anywhere`,并让所在弹性子项 `min-width:0`。
5. **表格不用 `overflow:auto`。** 放不下、或平均每列不足 92px(中文会被挤成竖条)就堆叠成"一行一块"(`assets/fit-tables.js` + `base.css` 里的 `.is-stacked`);≤420px 时标签在上、内容在下。`td/th` 用 `overflow-wrap:break-word`,**不要用 `anywhere`**(会把表格最小宽度压到一个字,导致永远"放得下"而不堆叠)。
6. 代码块 `white-space:pre-wrap; overflow-wrap:anywhere`,不用 `overflow:auto`。
7. 长公式缩小字号适配(`assets/fit-math.js`);缩到 70% 仍放不下的,用 `\\` 或 `aligned` 手动断行。
8. 图片、SVG、图表 `max-width:100%`;图表宽度取容器实际宽度并随容器重绘。
9. 触屏(`@media (pointer: coarse)`)点击目标 ≥ 44px;留出 `env(safe-area-inset-*)`。
10. `body{overflow-x:clip}` 只是兜底,**不能当作修溢出的办法**;溢出要从根上修。必须滚动的组件用 `scrollbar-width:thin`,且只作最后手段。

## 反小字准则

页面上最该省的是补充说明:图下一行小字、框旁的括号注释、大字下面再重复一遍的小字。读者要么不读,要么读了还是不懂。规定:

1. **少加补充说明。** 一个东西能靠名字、位置、线型自己讲清,就不另写说明。写完一句说明,先问删掉它读者会不会卡住。
2. **该讲的,用 LADR 的语言一次讲完。** 参照 Axler 的 *Linear Algebra Done Right*:先定义,再陈述,最后给注;每条短而完整;记号在第一次用之前讲清;零基础的读者只靠这一页就能读懂。说明写在讲解端(讲义)里,不散落在图和面板各处。
3. **一件事只讲一次。** 图例、记号、术语的定义只在讲义里出现一次,其他地方只引用它的编号。
4. **需要展开的,做成可交互的解释。** 术语带陶土下划线,点一下在原地展开定义,再点收起。默认只显示正文,读者要的时候才看到解释。
5. 字号下限:HTML 文字渲染后不小于 14px,SVG 文字实际渲染后不小于 12px。宽图在窄屏不缩小,改成分组清单。表单控件全局写 `button,input,select,textarea{font:inherit}`。KaTeX 上下标例外。
6. `scripts/check_viewports.py` 检查第 5 条。第 1 到 4 条靠交付前自查:数一数图下、框旁有几处说明文字,每一处都要能说出为什么不能放进讲义。

## 文案

中文为主,句子式,说"这是什么"而不是营销语;标题说内容,不说口号。数字带单位,小数位数一致;英文不全大写。按钮写动作("保存修改",不写"提交");空状态写出下一步该做什么;错误说清发生了什么和怎么办,不道歉。

## 无障碍与质量底线

- 正文对比度 ≥ 4.5:1;陶土色**不要**直接当文字色;按钮白字只放在 `--accent-strong` 上(放在 `--accent` 上只有 3.1:1);陶土底上要放字时用墨色。
- 键盘焦点可见(2px 墨色轮廓,偏移 3px);尊重 `prefers-reduced-motion`。
- 字体加载失败回退到系统无衬线;除字体和 KaTeX 外不引入外部依赖。

## 禁止清单(试过且效果不好的做法)

- 横向滚动条(表格、代码块、公式容器外层的灰色滚动条)。
- 任何圆角,包括圆点、圆形头像、胶囊按钮、SVG 柱子的 `rx`、圆头线帽。
- 荧光笔式的高亮底色(强调只用"下方一条线");页面切换过渡动画。
- 紫蓝渐变、粉彩卡片、悬停上浮、弹簧回弹动效(显得廉价)。
- 90 年代票据风:灰绿纸、绿条隔行、印章红、斜线填充、噪点、点阵大字、满页墨线框(显得粗糙)。
- 机场导视整层:黄色标识、顶部深色标识牌、`A1` 编码、每行英文小字、描边图标方块(不直观)。
- 构成主义装饰:贴图式几何(圆 / 楔形 / 斜线)、竖排旋转标题、通高大色条(缺乏质感);路牌式带钩带斜切的硬朗字标。
- 密集的"条形码"式刻度(每 8px 一根竖线的梳子);任何高饱和色;任何海军蓝;暖黄、米色底。
- 卡片框、投影、渐变、玻璃拟态、emoji 当图标、全大写标签、"→"追加在按钮后面。
- 进场淡入上滑动画。允许的动效只有:响应用户操作的小变化,主视觉数字的一次性滚动计数,以及计算图里由点击触发的"合并重复结构"折叠(见 `references/compute-graphs.md`,约 0.5 秒,缓入缓出,不回弹,不自动播放,尊重 `prefers-reduced-motion`)。

## 交付前自检

- 有没有横向滚动条、卡片框、阴影、渐变、噪点、圆角(含 SVG 的 `rx`/圆头)?应全部没有。
- 点缀色是否只有陶土一个、面积 < 1%?强调是不是"下方一条线"而不是底色?
- 选中态 + 悬停态叠加时字还看得见吗?
- 有没有"为了风格"但增加阅读成本的元素?有就删掉。
- 数字是否都 `tabular-nums`?有公式时是否已渲染、无残留分隔符?
- 深色模式本风格尚未设计;用户要求时先问清再做。

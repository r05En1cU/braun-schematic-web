# 定理原理图讲解法

这套做法要解决的是：一个形式化系统随着作者的思路长大，长到作者自己也读不懂了。讲解页要把它重新还给作者。读者能看出每条定理说了什么，看出定理之间怎么接，看出哪里断了。读者不需要会读 Lean，也不需要相信讲解者。

视觉令牌、字体、直角、无横向滚动、标点纪律，全部沿用本 skill 的 SKILL.md。本文件只写它没有覆盖的部分。

本文件的图是手写坐标的定理关系图，适合带证明的系统。要讲论文里的架构、公式推导或数据通路，用 `compute-graphs.md` 里的算符级计算图，它的布线由 `assets/schematic.js` 自动完成。两种图的讲义、术语展开和读者假设相同。

## 读者是谁

默认读者有这几个特点：

- 聪明，有一门硬工程背景，比如集成电路、原理图和布局布线。
- 不会读 Lean，看不懂裸 LaTeX，但愿意被拉着学。
- 不适合"举个最小闭环的例子"式的讲法，需要的是能一眼抓住结构的抽象形状。
- 读起来累的东西会拖垮理解：分步翻页、一件事讲两遍、小字重复大字。
- 无法自己核对模型的说法，所以模型在看不见的地方偷换概念是最大风险。

写作和画图前，先问自己一句：这个读者看了能不能复述"这条定理凭什么前提，给出了什么，交给了谁"。

## 七条总原则

1. **先有故事，再有零件。** 每张图只讲一条主线。先用一句话写下这条主线，再决定画哪些框；不能为主线服务的东西放进点开后的面板里。
2. **手挑，不倾倒。** 子代理提取出来的规格是素材，不是图。把规格里的东西全画上去，框会太多，主线就被淹没。框的位置和线的走向都手写坐标；自动布局只用来验证，不用来决定画面。
3. **保证贴在它说的那个东西旁边。** "相等"挂在两个值之间，"旧候选仍在"贴在档案字段旁边。不要把所有结论单独排成一列，让读者自己去对。
4. **数据和证明分两种线。** 实线是数据真的流过去，虚线是证明依赖。程序框只接它真的读的输入。比如一个程序不读模型和预算，就不能把模型和预算连到它上面；这种"程序不读什么"本身就是值得让读者看见的信息。
5. **事实、核对过的、推断、未确认，四种分开写。** Lean 证过的写"证了"；子代理对照源码核对过的写出处；自己的推断要说明是推断；读者还没确认的不写成定论。
6. **断开的地方明说。** 没有调用者、只给存在不给形状、只对某一族成立、只按栈序：这些边界要写在图上和讲义里，不能藏起来。断开处画成红框或浅色框。
7. **能机械检查的都要检查。** 包括引用指向的行、线有没有穿过框、筛选组里列的框是否存在、各种宽度下有没有溢出。读者没法替你查。

## 页面的三层

一个页面里放三层，都在同一个单文件 HTML 里：

1. **顶层原理图。** 每条主线定理画成一个器件，器件之间的线上写着"流过去的是什么"。
2. **器件的语义流程图。** 点进一个器件就看到它：程序读什么、产出什么，定理凭哪些前提给出哪些保证，这些东西从哪个器件来、到哪个器件去。
3. **数学讲义。** 放在流程图正下方，LADR 风格，和图联动。

另外有一个点击面板，用来显示选中对象的说明和 Lean 原文。页面末尾还有一节检查报告，形式类似电路的 ERC。

导航用面包屑："主线 / T05 支配与剪枝"。每层右侧有一排筛选按钮。调用图作为子图的一个切换视图保留下来，给检查用，不当作主视图。

## 顶层原理图

**器件框：**
- 框尺寸 180×92，左上角写编号（Barlow Semi Condensed），框中间写短标题，下面一行小字写"点开看语义流程"。
- 没接入主线的器件，用浅色虚线框画，放在底部一行，并写一句说明。

**线的规则：**
- 线上写的是流过去的是什么，例如"剪枝的子集和覆盖""只借 cancelMacro"，不超过 8 个字。不写调用次数。
- 线型：
  - 墨色实线：保证被对方拿去用。
  - 灰色点线：只借用了程序，没有用定理。
  - 红色虚线：文档声称有这条依赖，但代码里没有。
- 走线一律正交，路径手写，例如 `M210 110 L250 110 L250 215 L550 215`。
- 标签位置手写坐标。标签不能压在框上；标签和其他线相交时，给标签垫一块底色，盖住那段线。
- 线交叉的地方不表示连接，和原理图一样。

**点线以后：**
- 面板列出这条线里的每一份东西：它从哪个保证或产物出发，落到对方的哪个前提或定理，出处在哪个文件第几行。
- 同一份东西如果两边各记了一次，就出现两行。

**顶层右侧的筛选：** 只有一个按钮，"显示文档写了但代码里没有的线"。

## 器件语义流程图

这一层是整套做法的核心。标准样子是"一轮恢复"那种图：输入在左边分组，程序在中间，产物在右边，结论贴在产物旁边，证明在下半部分，交给下一轮或下游的东西在底部或右侧。

### 网格和尺寸

- `viewBox` 宽 1130，高按内容定，一般在 600 到 900 之间，桌面上接近 1:1 显示。
- 五列：
  - 第 1 列 x=20，宽 180，放输入和前提；
  - 第 2 列 x=260，宽 170，放由输入构造出的东西和中间程序；
  - 第 3 列 x=450，宽 170，放主程序和定理；
  - 第 4 列 x=700，宽 180，放产物、保证和流进来的器件；
  - 第 5 列 x=940，宽 170，放结果、值和流出去的器件。
- 窄屏处理：窄于约 1100px 时隐藏 SVG，改为按列分组的 HTML 清单（每项写名字、说明、交给谁），点击同样打开面板。图整体缩小后文字会低于 12px，反小字准则见 SKILL.md。
- 框高 40 到 64；主程序和大产物可以高到 90 到 180。同一列的框之间至少隔 10。
- 每张图 15 到 25 个框。超过 25 个时，拆成上下两段，中间画一条分隔线，每段一个小标题，比如"规则只追加边的时候"。

### 框的种类和画法

| 种类 | 用途 | 画法 |
|---|---|---|
| in | 输入 | 底色 #E8EBEE，墨线 1.5 |
| prog | 程序或定义里的计算 | 底色 #DDE1E5，墨线 2；标题是英文标识符时用等宽字，是中文时不用 |
| prod | 产物 | 墨线 2；里面有字段时标题置顶，字段画成内框 |
| pre | 前提，只给定理用 | 灰墨虚线 |
| thm | 定理层 | 灰墨虚线，标题写"定理"，副标题写"Lean 证明"；一个故事只用一个 |
| gua | 定理给出的保证 | 底色 #F3F5F7，左侧一条 4px 陶土竖条 |
| ghost | 别的器件 | #97A0AA 虚线；第一行写"从 T07"或"到 T12"，第二行写流过来或流出去的是什么 |
| faint | 重画的输入，或者旁证、旁支 | 灰线，灰字 |
| bad | 断开的地方 | 红线，左侧一条 4px 红竖条，红字 |

框里的文字用 `fitFs` 缩字号来适配宽度，不换行。主标题 17px，大框 20px，最小 13px；副标题 14px，最小 12px。缩到最小还放不下，就加宽框或改短文字，不再缩小。

### 线、相等连接和注记

线的种类：

| 种类 | 含义 | 画法 |
|---|---|---|
| data | 数据流 | 墨色实线 1.5，墨色箭头 |
| proof | 证明依赖 | 灰墨虚线 `5 4`，灰色箭头 |
| tie | "这条保证说的就是这个" | 陶土实线 2.5，不带箭头 |
| loan | 只借程序 | 灰色点线 `2 3` |
| bad | 通向断开处 | 红色虚线 |

另外三种配件：

- **相等连接（ties）。** 两个值之间画一条竖直的陶土粗线，中间放一个 50×26 的标签"相等"。证了但没有调用者的，画成灰色虚线版本。
- **注记（anns）。** 贴在产物下方的一两行小字，比如"原前沿的子集"，可以点击。证明线的箭头指向产物的下边沿，注记文字放在箭头右侧，不能被箭头穿过。
- **框组（frames）。** 用一个大虚线框把几个子程序框起来，表示它们合起来是一个程序，比如"开始、逐站、收尾"三段合成一次取消。框组的标签写在框内的左下角，不能放在有线穿过的地方。

走线规则：

- 只用正交线，每条最多三个拐点。线的终点离目标框 4px，箭头尖刚好碰到框边。
- 很多前提都汇进同一个定理时，用总线：每条前提先水平走到同一个 x，再一起拐进定理。重合的线段在视觉上合成一根，是允许的。
- 定理也会"谈论"输入，但不要画定理到输入的线。这种线会和数据线缠在一起。改为在定理面板里列一项"它谈论的输入"。
- 某个器件同时向两个去处输出、而这两个去处的意义不同时，比如一个进主结论、一个只进旁支，要拆成两个框分别画，不能合成一个。
- 一条线不能穿过非端点的框。线挡住小标签时，把标签挪开。

### 筛选按钮

每张图有一排筛选，按这张图自己的意义分组，不套通用模板。常见的组有：

- "决定最优值的"或"决定答案值的"；
- "只决定留下谁的"或"影响选哪个方案的"；
- "只影响开销的"；
- "证明要的前提"；
- "规则更新时"；
- "交给别的器件"。

另外固定两个按钮："数据线"和"证明线"，按线的种类自动筛。

规则：

- 一个组只列框，组内的线自动取两端都在组里的那些。
- 组名要准确，不能误导。比如组里有决定新值的程序，组名就不能叫"不改值的"。
- 被筛掉的框透明度 0.15，被筛掉的线透明度 0.1。

### 面板里的说明

每个框、相等连接、注记、内框，都要有一条 info：

```js
info: { id: {
  k: '输入，决定最优值',   // 种类，加上它在这张图里的角色
  t: '前沿 frontier',      // 标题
  x: '一两句到四五句的正文',  // 它是什么，起什么作用，边界在哪
  l: 'frontier : List (Candidate S)',  // Lean 名字或签名，或者出处的文件和行
  refs: ['Minimal/Dominance/Frontier.lean:132-136'],  // 要在面板里展示原文的 Lean 引用
  go: 'T11'                // ghost 框可以跳转去的器件
}}
```

点一个框时，和它相连的线变成陶土色，其他东西变淡。再点一次就取消选中。面板右栏依次放三样：讲义里说到这个框的条目链接，Lean 原文，原文的出处。

```js

// 连线：[源, 汇, 种类, 手写路径]
const HAND = { T05: {
```

渲染只做一件事：按数组顺序依次画出框组、标签、线、相等连接、注记、框、内框。透明度由三件事决定：当前选中的框、当前筛选、讲义带过来的聚焦。不要在渲染时自动布局。

必须有的辅助函数：

```js
function tw(s,fs,mono){let w=0;for(const ch of String(s))w+=/[⺀-￯]/.test(ch)?fs:fs*(mono?.6:.55);return w}
function fitFs(s,w,base,min,mono){let f=base;while(f>min&&tw(s,f,mono)>w)f-=.5;return f}
```

SVG 里要预先定义五种箭头：墨色、灰墨、陶土、红、灰。所有 rect 都是直角，所有 path 的端点和拐角都是方的（linecap 用 butt，linejoin 用 miter）。

## 数学讲义（LADR 风格）

讲义的样子参照 Axler 的 *Linear Algebra Done Right*：先给定义，再给定理，最后给注；每条短而完整；记号在第一次用之前讲清楚；直觉紧跟在式子后面。不加例子，不写证明。

### 每一条的结构

```html
<div class="li" id="L5-3" data-n="sound check">   <!-- data-n 列出这一条说到的图上框 id -->
  <div class="lh"><span class="no">5.3</span><span class="ty">定义</span><span class="nm">支配，和可靠的检查器</span>
       <span class="lean">Lean 名字，没有调用者时在后面注明</span></div>
  <div class="fm">\[ ... \]</div>
  <p>一到三句：读作什么，直觉是什么，边界在哪。</p>
</div>
```

讲义的第 0 条固定是"记号"，在每一页都显示。它要讲清楚（图例也放在这里，写成定义，图下不另加说明）：

- `f : A → B` 的意思；
- ℕ；
- ∀、∃、∧、∨、¬、⇒、⇔；
- ∈；
- some 和 none；
- 截断减法；
- "定理都写成前提推出结论"。

### 写式子的规则

**形式上的规定：**

- 每条定理都写成"前提 ⇒ 结论"。定义用 `:⇔` 或 `=`。归纳定义用横线规则：横线上面写条件，下面写结论。
- 式子长了就用 `aligned` 或 `gathered` 分行，每行不超过 70 个字符左右。
- 条件分支用 `cases`，条件本身用符号写，不用 `\text{否则}`。KaTeX 的 `\text{}` 里不能放中文，因为字体子集化之后中文会显示不出来。英文句子也不要塞进式子，改成谓词，比如 `\mathrm{IsRunning}(t,j)`。

**允许做的改写：**

- 换记号，比如 fuel 写成 h，候选的两个分量写成 x₁、x₂；
- 省略隐式参数；
- 把 Option 和列表写成数学记号；
- 把 structure 的各个字段写成合取。

**不允许做的改写：**

- 漏掉前提，比如"不是终态"、"已停机就原样返回"这类短路分支；
- 漏掉结论里的某一项；
- 把一般形式和特例混在一起；
- 把单向结论写成相等；
- 把"只说存在"写成"刻画了结果"。

**解释文字的规定：**

- 不解释"="这类显然的东西。
- 一件事只讲一次，不在大字下面用小字再说一遍。
- 有缺口要明说，比如"只保值，不保费用集合"，"none 只对这个预算说话"。
- 讲义里引用别的器件，用编号写，比如"这一项来自 T07 的 7.6"。

### 和图联动

- 点讲义的一条，就把 `st.focus` 设成这条的 data-n。图上只留下这些框，以及两端都在里面的线，其余的框透明度 0.18、线 0.1。图如果不在视口里，就滚上去。再点一次取消。
- 点图上的框，就高亮讲义里 data-n 包含这个框的条目，并在面板里列出这些条目的链接，点链接会滚到对应条目。
- 讲义的源文件按器件分块，写在隐藏的 store 里，由构建时的 KaTeX 预先渲染。切换器件时，把对应的块拷进可见区。查找元素要限定在可见区里（`#lecBody #id`），因为隐藏区里有同样的 id。


## 让 Lean 内容可信的流程

### 分工

- 讲解者自己不读 Lean，也不写证明。读 Lean 的工作交给 Opus 级的子代理。
- 需要新的 Lean 证明时，交给专门的形式化工人去写，讲解者只用它通过检查的结果。
- 每个子代理的任务说明和原始回复，都逐字存进工作区的 `subagent-log/NN-名字-brief.md` 和 `-reply.md`。上下文压缩之后，从子代理会话文件里逐字提取，并注明是提取的。
- 任务说明里不放讲解者自己的假设，也不允许子代理读讨论目录，以免它被带着走，失去独立性。

### 三种子代理任务

**1. 规格提取。** 每个子代理负责两个器件，交回 JSON 和一段语义说明。JSON 的形状：

```
{part, question, groups[],
 inputs[{id,label,sub,group,lean,note}], programs[{id,label,sub,lean,reads[],note}],
 products[{id,label,sub,from,lean,note}], premises[{id,label,sub,kind,lean,note,source}],
 theorems[{id,name,ref:"Minimal/...lean:a-b",uses[],gives[],note}],
 guarantees[{id,label,sub,about[],lean,note}],
 upstream[{from,to[],carries,loc,note}], downstream[{to,from[],carries,loc,note}],
 broken[], corrections[]}
```

`corrections` 用来写子代理发现的、和以往接线表或文档不一致的地方。每个子代理都要独立地对照源码复查。

**2. 图的复核。** 把手画数据文件和规格原文交给一个新的子代理，让它逐条对照源码核对：

- 说"有调用者"或"没有调用者"的地方；
- 说流向哪个器件的地方；
- 前提和结论有没有反；
- 箭头方向；
- "相等"的两边是不是真的相等；
- 程序框是否真的读了连进来的输入；
- 筛选组的组名会不会误导。

**3. 讲义复核。** 逐条对照 Lean 核对数学式，核对时列出上面"允许做的改写"和"不允许做的改写"两张清单。

复核的回复格式：先一句总体判断，然后只列有问题的条目，每条写原文、问题、Lean 依据和建议的改法，最后单列"拿不准的"。复核意见全部照改。改完在页脚写一句：经过几号复核，改了多少处。

### 常见的走样

以下几类走样在实践中都出现过，写说明时要逐条自查：

- **把"某类东西里没有残留"读成"没有某类东西"。** 例如"已取消的会话不留事件"被写成"没有已取消的会话"。
- **把"只读某几样"说宽了。** 例如"静默步只动控制位"，实际上静默步还会写宏实参。
- **把单向的界写成相等。** 例如"成本模拟下值不变"，实际上只能推出"替代方不更差"。
- **把两个去向不同的来源合成一条线。** 结果是让一个只进旁支的结论，看起来支撑了主结论。
- **漏掉短路分支和边界前提。** 例如"已停机就原样返回"，"只在不是终态时才能走边"。
- **把面向开发者的工作记录写进读者文字。** 例如"某某号回复说了什么"这类话，不该出现在给读者看的说明里。

### 机械检查

**构建时检查：**

- 每条定理引用指向的那几行里，必须出现定理名字。
- Lean 原文在构建时从源文件读取，用 pygments 的 lean4 高亮，带上行号。引用会从陈述行往下延伸到证明结束，最多 46 行。
- KaTeX 在构建时预先渲染，`throwOnError:true`。
- 字体子集化后以 base64 嵌入。要报告缺字。⟨⟩ 这类符号用 Noto Sans Mono 兜底，并把它放进 sans 的字体栈。

**页面检查（Playwright），覆盖 360、390、768、1024、1440、1920、2560 七种宽度：**

- `scrollWidth` 等于 `innerWidth`，页面不能横向溢出；
- 不出现圆角，没有 katex-error；
- 每个框都能点开，并且有说明；
- 带 refs 的框，面板里确实出现了代码块；
- 每个筛选按钮、视图切换都点过一遍，没有 js 报错。

**几何检查（在页面里跑）：**

- 框和框不重叠；
- 线段不穿过非端点框（用线段和矩形求交，起点或终点所在的框除外）；
- 箭头终点离目标框边不超过 6px；
- 注记和小标题的文字框不压在任何框上；
- 所有框都在 viewBox 以内；
- 筛选组和讲义 data-n 里列出的 id 都存在。

**交付前：** 用眼看 1440 和 390 两种宽度的截图。检查通过了，不代表图看着舒服，这两件事不是一回事。

### 已知的坑

- headless Chromium 缺 libXdamage 时，用 `apt-get download` 下载后，设置 `LD_LIBRARY_PATH`。
- SVG 上重叠的元素，用 `dispatchEvent('click')`，不要用 `click({force})`。
- 截图直接写进挂载目录会报 EINVAL，先写到 /tmp，再拷过去。
- 溢出检查要排除 `.katex-mathml`。
- 很长的文件路径要加 `overflow-wrap:anywhere`。

## 语言风格

**句子和措辞：**

- 短句，先说结论。一个意思只说一次。
- 主语清楚，比如"程序只读检查器和前沿"，不写"会被读取"。
- 同一个东西从头到尾用同一个名字。第一次出现时给出它的 Lean 名字，之后用中文名。
- 数字和范围写准，比如"16 条""第 126 行""长度不超过 3"。

**边界和置信度：**

- 边界用"只"字说清楚：只说存在，只对旧模型证过，只按逆序，只到旁支。
- 说没有调用者，要先查过；拿不准就写"我没有核对"。
- 评价性的话要标明是评价，并说明还没经过检查或读者确认。

**题材上的规定：**

- 不写 AI 腔：不用"让我们""值得注意的是""本质上""赋能"。
- 不用"举个例子""最小闭环"开头。讲法是抽象的形状加上准确的定义。
- 可以借用读者熟悉的领域打比方，比如器件、管脚、ERC、悬空、原理图，但比方只用来定位，不能代替定义。
- 标点遵守 SKILL.md：不用破折号、书名号、装饰性引号来制造设计感。

**结构上的规定：**

- 页面标题说清楚这张图是什么，副标题说明怎么读。
- 图下面不放提示行。线型、框的种类这类图例，写成讲义第 0 条的定义，一次讲完，术语做成点击展开。
- 面板正文不超过五句，只写这个框特有的内容，不重复讲义里已经讲过的定义。

## 为什么这样写

**读者的瓶颈在于对不上号，不在于缺信息。** 形式化项目里的信息往往太多。读者真正缺的，是"这条结论说的是哪个东西""这个前提从哪来"。所以图把保证贴在它说的数据旁边，把前提的来源画成线。讲义里的每一条又能点亮图上的框。三处说的是同一件事，读者在三处之间来回对照，自然就对上了。

**手挑比自动完整更诚实。** 自动布局看起来客观，其实把判断交给了算法：所有东西一样重，主线就被淹没了。手挑需要讲解者先想清楚故事，这一步本身就逼着讲解者真的理解了。被挑掉的细节不会消失，它们都在面板里。

**LADR 的顺序符合直觉推进。** 先定义对象，再陈述关于对象的事实，每个事实都是"给我这些，我还你那些"。零基础的读者不需要先学一门语言，只需要跟着记号一步步往前走。不写证明，是因为读者需要的是用得上的接口，不需要实现细节，实现细节已经由 Lean 检查过了。

**把置信度写在明处，是对抗偷换概念的唯一办法。** 讲解者是一个模型，它会在不知不觉中把"没有残留"说成"没有"。读者自己没法查。所以这套做法安排了独立的子代理复核、逐字日志和机械检查，并把"证了""核对过""我的推断"分开写出来。读者不必相信讲解者，只需要知道每一句话靠的是哪一层证据。

**克制的视觉让结构成为唯一的信号。** 底色冷灰，全部直角，只有一个陶土色点缀，所以图上任何一处变化都有意义：陶土竖条表示这是你拿到手的保证，虚线表示这是证明，红色表示这里断了。装饰越少，读者越不用猜。

## 实践中效果不好的做法

下面这些做法都试过，读者反馈效果不好：

- **像备忘录一样的长文页，配系统字体。** 图在这种页面里成了配角，读者读不下去。
- **放了 LaTeX 公式，却没讲怎么读。** 公式成了装饰。
- **分步翻页的 stepper。** 读起来太累，读者想要一屏就能看到全部结论。
- **类型交代不全。** 读者分不清一个东西是函数还是元组。
- **一件事讲两遍。** 大字说一次，下面小字又说一次。
- **只画调用图，不画语义流程。** 读者知道了谁调用谁，却不知道东西是怎么流动的。
- **按规格全量自动布局。** 五十多个框，线挤在框之间的缝里，排成一束一束的，图很宽，缩下来以后字太小。
- **调用图的排线太密。** 线距要放宽到大约 14px。
